# PEAK — каталог и пополнение

Лиственная — склад-отправитель. Директор магазина оформляет заявку на сайте. Директор Лиственной проверяет её, вручную оформляет «Перемещение товаров» в 1С и указывает номер документа на сайте. Отправка заявки сама по себе не резервирует товар.

## Запуск обмена с УТ 11

Целевая конфигурация — УТ 11.5.25.61, платформа 8.3.27.1559. Выгрузка из 1С должна получать количество, доступное к перемещению, из тех же данных, что использует складская работа. Запрос к регистрам и сопоставление склада, характеристики и базового артикула нужно проверить на копии базы. Коды в примере условные до сверки с 1С.

1. В Sites дать доступ рабочим аккаунтам и задать серверные переменные. `PEAK_ACCESS` — JSON с привязкой email к роли, `PEAK_STOCK_LOCATIONS` — полный перечень кодов складов через запятую, `PEAK_SYNC_TOKEN` — отдельный случайный секрет.
2. Выдать обработке 1С сервисный доступ к приватному сайту. Хранить его и секрет обмена в закрытых настройках 1С. `POST /api/sync/stock` требует заголовки `OAI-Sites-Authorization: Bearer <сервисный токен Sites>` и `Authorization: Bearer <PEAK_SYNC_TOKEN>`.
3. Настроить регламентное задание в центральной 1С на каждые 30 минут. Передавать полный снимок с одинаковой датой, включая пустые склады, одной отправкой. При временном сбое повторять с той же датой. Успешный повтор возвращает `applied: false`. При сохранении сбой не меняет последний удачный снимок.
4. Сверить тестовую выгрузку с отчётом по Лиственной и магазину. Проверить совпадение на нескольких артикулах с разными цветами и размерами, склад с нулевым количеством и вариант товара, которого ещё нет в каталоге. Затем проверить заявку обеими ролями.

В `1c/PEAK_ОтправкаОстатков.bsl` — процедура HTTPS-отправки подготовленного JSON. Она не запускалась на рабочей базе и не содержит запроса к регистрам. Перед использованием проверить её в тестовой базе.

`PEAK_ACCESS`:

```json
{
  "store@example.com": {"role":"store","store":"etazhi","name":"ТЦ «Этажи»"},
  "warehouse@example.com": {"role":"warehouse"}
}
```

`PEAK_STOCK_LOCATIONS=listvennaya,kadyrova,nalchik,vesna,etazhi`. Код главного склада в API — `listvennaya`.

Тело запроса:

```json
{
  "updatedAt": "<ISO 8601 с часовым поясом>",
  "locations": [
    {"id":"listvennaya","rows":[["EXT263547B","black","40",11,"Кеды skate PEAK"]]},
    {"id":"etazhi","rows":[["EXT263547B","black","40",2,"Кеды skate PEAK"]]}
  ]
}
```

Строка содержит артикул, цвет, размер, целое количество и необязательное название. Для каждой комбинации артикул + цвет + размер суммировать данные внутри склада. Цвет и размер берутся из характеристики. Для товара без размера используется пустая строка. Пропущенные позиции в загруженном полном снимке считаются нулевыми. Отрицательный остаток показывается со знаком из отчёта, доступное для заявки количество в таком случае равно нулю. Новые варианты из 1С появляются в каталоге с доступными данными, фотографии берутся из исходного файла и сопоставляются по артикулу и цвету. Для новых моделей без фотографии показывается заглушка.

### Проверка по отчёту «Остатки и доступность товаров»

Конвертер `1c/import_stock.py` (Python с `openpyxl`) читает форму отчёта из примера «САЙТ.xlsx». Он находит колонки «В наличии» по названиям пяти складов, берёт артикул из своей колонки или из названия в скобках, разделяет характеристику по `|` и проверяет суммы по каждому товару и складу. Товарные строки без артикула исключаются с указанием строки и количества. Для боевого снимка передать `--updated-at` с временем формирования отчёта и часовым поясом. Итоговый JSON можно отправить через серверную процедуру из шага 2, когда отчёт или аналогичные данные формируются в центральной 1С автоматически.

## Сборка

`node build.mjs` копирует приложение и готовые ресурсы в `dist`. SQL в `drizzle/` применяется при публикации. Режим демонстрации показывает данные из «САЙТ.xlsx» и позволяет переключаться между магазинами и Лиственной. Тестовые заявки хранятся в браузере. Боевой режим использует D1, серверную авторизацию для заявок, защиту от повторной записи и блокировку отправки при остатках старше 75 минут.

## Публичные исходники

В примере остатки пустые. Для доступа владельца к предпросмотру задайте PEAK_OWNER_EMAIL в окружении сервера. Фотографии находятся в assets/photos, при сборке распаковываются автоматически. Для сборки нужны Node.js и Python 3. Выполните npm run build.
